The Foundation

The 3-Layer Architecture

Playwright relies on a language-agnostic RPC architecture divided into three distinct layers. Only the Browser Binary hasn't started yet — that happens in Step 2.

Layer 1

The Client (Your Test)

Written in TypeScript, Python, Java, or C#. This is your test code — where actions like the one below get called.

await page.click('#submit')
Layer 2

The Playwright Server (The Driver)

A Node.js background process that acts as the translator between your test code and the browser's native protocol.

Layer 3

The Browser Binary

Chromium, Firefox, or WebKit, running as a separate OS process — dormant until the Driver launches it.

01 Step 1

Initialisation & Handshake (The Driver Boot)

You run npx playwright test. The Client spawns a local background process executing the Playwright Driver, then establishes a persistent connection over stdio or a WebSocket. They exchange JSON-RPC handshake messages to verify API version compatibility.

02 Step 2

Browser Instantiation

Your code executes chromium.launch(). The Driver goes to your local ms-playwright folder and executes the raw browser binary, launching it with flags that expose its debugging port for CDP (or the Firefox/WebKit equivalents).

Inside the browser, several actionability checks run before the click is ever dispatched:

  • Locate the element
  • Scroll it into view
  • Actionability checks (visible, stable, enabled)
  • Dispatch trusted OS-level mouse event
04 Step 4

The Response Loop

The browser registers the click and updates its state, sending a completion event via CDP back to the Driver. The Driver routes a success response to the Client over the same stdio stream, and your test's Promise resolves.

05 Step 5

Teardown & Process Cleanup

When the test finishes or fails, the Client sends a close message down the pipe. The Driver sends a terminal command to shut down the browser contexts, issues a SIGTERM signal to kill the browser binary, then exits itself — freeing every local resource it held.
